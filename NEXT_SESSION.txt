6. REUSE POINTS / CRITICAL GEOMETRY CAUTION
The old assembly functionality STILL EXISTS in the kernel, but is not exposed in the main UI:
- designer/kernel/validate.mjs: assembly(input, progress=1, opening=.75), assemblyAudit().
- designer/kernel/index.mjs: evaluatePose(spec,{mode:'assembly',progress,targetOpening:.75}); API design.pose supports this state.
- designer/ui/async-controller.mjs: pose(), frame(spec,'assembly').
- designer/kernel/geometry.mjs: unfold(), model(), panelWorld(); net.hinges, net.seam, net.ends, folds and seals metadata.
Main normal strip order: bottom, left-lower, left-upper, top, right-upper, right-lower.
Hinge edges: A-D, K-L, E-J, F-G, M-N; closing seam B-C. Solid hinge indices [2,3,5] in the unfolding loop.
For the ordinary strip, the second marked solid crease corresponds to the boundary before the top panel (E-J). Verify coordinates/orientation instead of relying only on this note.

CRITICAL: current assembly() interpolates ALL hinge angles synchronously from the open net to a .75-open target. It is NOT a validated first-fold/seal/side-fold/end-seal manufacturing sequence. Do NOT simply divide progress into arbitrary equal segments and label them as fabrication steps.
The first half-fold plus sealed pouch can be a different planar configuration from the collapsed pose of the existing actuation path. Establish a continuous rigid-panel, seam-preserving path between stages; do not jump between them, stretch panels, or change their areas.
End film is not modeled as a complete 3D membrane. Current seal guides are experimental. Do not claim paired end-film lines truly coincide unless modeled/verified; clearly separate instructional markers from a manufacturing certificate.
First deliver a validated sequence for the ordinary rectangular box. Do not invent a plausible animation for every generalized geometry; return a supported/unsupported diagnostic from the kernel when necessary.

Suggested architecture for the next feature:
- Kernel/neutral assembly module returns stage IDs, operation type (fold/seal/inlet), rigid placements, geometric cue anchors/line pairs and support diagnostics.
- API exposes assembly stages and a pose/transition for stage + local progress. Keep existing design.pose assembly compatibility where possible.
- UI owns labels, < > buttons, transition timing and "Seal here" rendering. No folding equations in DOM handlers.
- Use ONE camera frame covering the flat net and all stages; avoid automatic zoom changes or perspective tricks that make rigid plate areas appear to change.
- Test panel distances/areas, continuous transitions, closure after sealing, and agreement of seal cue coordinates; verify controls forward/back and clean exit in the browser.
